# Правила работы AI-ассистента в этом репозитории

Это учебный репозиторий с лабораторными работами курса по DevOps/облачным технологиям.

**Главный документ — `AGENTS.md` курса** (в корне репозитория с заданиями). Правила ниже его не отменяют и не ослабляют: они только добавляют контекст конкретно этого проекта. При любом противоречии приоритет у курсового файла.

Отвечай по-русски.

---

## 1. Контекст проекта

**Сервис:** «МаркетГрад» — вымышленный интернет-магазин электроники и товаров для дома. Придуман в Лабе 1 и используется как сквозной пример во всех последующих лабах. Не заменяй его на абстрактный `example-service` и не придумывай новый — все лабы должны описывать одну и ту же систему.

**Ключевые сущности предметной области** (используй их в именах эндпоинтов, топиков, таблиц, метрик):
`products` (каталог), `cart` (корзина), `orders` (заказы), `payments` (оплата), `users` (личный кабинет), `delivery` (доставка), `stock` (остатки склада).

**Состав системы:**

| Компонент | Что делает | Порт |
| --- | --- | --- |
| Web-фронтенд (Next.js SSR) | витрина, страницы товаров | 3000 |
| API-бэкенд (REST) | `/api/*`, `/orders/*`, `/cart/*`, `/auth/*` | 8080 |
| Поиск (OpenSearch) | полнотекстовый поиск по каталогу | 9200 |
| PostgreSQL | заказы, пользователи, товары | 5432 |
| Redis | сессии, корзина, кэш | 6379 |
| Workers | оплата, уведомления, обработка картинок | — |

**Сетевые решения из Лабы 1** (менять только если студент сам так решит):

- VPC `10.20.0.0/16`, регион `ru-central-1`, три зоны доступности `a`/`b`/`c`;
- public `10.20.0.0/24`, `10.20.1.0/24`, `10.20.2.0/24` → IGW;
- private `10.20.16.0/22`, `10.20.20.0/22`, `10.20.24.0/22` → NAT своей зоны;
- data `10.20.32.0/24`, `10.20.33.0/24`, `10.20.34.0/24` → NAT + VPC Endpoints;
- внешний ALB (L7) с path-правилами, внутренний ALB для поиска, NLB — только в планах;
- три NAT Gateway (по одному на AZ), Direct Connect + Site-to-Site VPN с BGP;
- on-premise сети компании: `10.0.0.0/16` и `192.168.0.0/16` — новые диапазоны не должны с ними пересекаться.

## 2. Структура репозитория

```
marketgrad-cloud/
├── README.md          # описание проекта, авторы, список лаб
├── AGENTS.md          # этот файл
├── report.md          # сквозной отчёт: по разделу на каждую лабу
├── scheme/            # схемы (png + исходники svg/mermaid)
└── lab-N/             # код и конфиги конкретной лабы
    ├── README.md      # что и как поднято в этой лабе
    ├── docker-compose.yml
    ├── configs/
    └── screenshots/
```

Правила размещения:

- работа каждой лабы — в свою папку `lab-N/`, её описание — **отдельным разделом в общем `report.md`**;
- схемы — в `scheme/`, растр и исходник рядом, на исходник ссылаться из отчёта;
- ничего не удалять и не переписывать из предыдущих лаб без явной просьбы: отчёт накапливается, а не заменяется.

## 3. Оформление отчётов

- Markdown, заголовки разделов — `##`, вложенные — `###`.
- Таблицы — там, где задание требует таблицу (подсети, балансировщики, Security Groups). Не заменять их списками.
- Каждое техническое решение сопровождается обоснованием в 2–4 предложениях: почему такой выбор, что было бы при альтернативе.
- Термины и названия сервисов — как в заданиях курса (ALB/NLB, Security Group, NAT Gateway, VPC Flow Logs).
- Чек-лист самопроверки в конце раздела заполняется честно: не ставить галочку напротив того, что не сделано.
- Контрольные вопросы — по одному ответу на вопрос, без воды, с опорой на материал лабы.

## 4. Технические ограничения

- **Платные облачные ресурсы не поднимаются.** Лабы проектные — архитектура описывается и рисуется, а не разворачивается. Если ресурсы всё-таки создаются, ассистент напоминает удалить их после сдачи.
- **Локальный стек — только `docker compose`**, версии образов фиксируются тегами (`grafana/grafana:11.3.0`, а не `latest`), чтобы работа воспроизводилась у преподавателя.
- **Секреты не коммитятся.** Пароли и токены — в `.env` (в `.gitignore`), в конфигах остаются плейсхолдеры. В примерах — заведомо учебные значения, не настоящие.
- **Числа, цены и лимиты провайдеров ассистент по памяти не подставляет** — они устаревают. Студент берёт их из калькулятора/документации провайдера, ассистент указывает, что именно смотреть.
- Схемы: Mermaid, если задание допускает диаграмму текстом; иначе SVG с экспортом в PNG.

## 5. Как вести работу над лабой

Порядок тот же, что в курсовом `AGENTS.md`:

1. Назвать части лабы.
2. Идти по одной части: что делаем, зачем, минимум необходимого.
3. В точках реального выбора — один вопрос на проверку понимания, без допроса.
4. Для проектных лаб — **сначала вариант студента и его обоснование, потом оформление формулировки в отчёт**.
5. Подопытные сервисы (заглушки, продюсеры/консьюмеры) генерируются сразу и целиком: программирование не цель курса.

Чего не делать:

- не выдавать конфигурацию мониторинга/инфраструктуры одним куском, даже если просят;
- не решать за студента, что изображено на схеме и какие варианты он выбирает;
- не переписывать уже сданные разделы отчёта без запроса.
